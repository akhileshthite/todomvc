## 1. 🔴 The contract source is not in the repository

- [x] Addressed
- [ ] Dismissed

`.gitignore:7` ignores `contracts/`. A gitignore pattern with a trailing slash
and no leading slash matches a directory of that name **at any depth**, so it
also matches `src/contracts/`. The intent was to ignore the generated
`contracts/` directory at the repo root only.

The result is that `src/contracts/identity.js`, the only contract in the
project and the thing the whole example is about, was never committed:

```
$ git ls-files src/contracts/
(nothing)

$ git check-ignore -v src/contracts/identity.js
.gitignore:7:contracts/    src/contracts/identity.js
```

A fresh clone fails at the first step. `npm run contracts` calls
`copyFile(at('src/contracts/identity.js'), ...)` in
`scripts/build-contracts.mjs:44`, which throws `ENOENT`, so `npm start` never
gets to the build or the server.

Anchor the pattern to the root:

```diff
 # Generated by `npm run contracts`
-contracts/
+/contracts/
 chelonia.json
 src/contracts/manifests.json
```

Then `git add src/contracts/identity.js` and amend. Worth also checking the
other patterns with the same shape: `build/` and `data/` are only ever
generated at the root, so `/build/` and `/data/` are more accurate too.

## 2. 🟡 `npm run serve` silently does nothing if the checkout path has a space

- [x] Addressed
- [ ] Dismissed

`scripts/chel.mjs:32`:

```js
if (process.argv[1] === new URL(import.meta.url).pathname) {
```

`URL.pathname` is percent-encoded, `process.argv[1]` is not:

```
$ node -e "console.log(new URL('file:///Users/a b/todomvc/scripts/chel.mjs').pathname)"
/Users/a%20b/todomvc/scripts/chel.mjs
```

Any path containing a space or a non-ASCII character makes the comparison
false. The module then exports `chel` and exits 0 without running anything, so
`npm run serve` looks like it succeeded and no server starts. `~/My Projects/`
is enough to trigger it, and that failure is very hard to diagnose because
there is no output at all.

```diff
+import { fileURLToPath } from 'node:url'
...
-if (process.argv[1] === new URL(import.meta.url).pathname) {
+if (process.argv[1] === fileURLToPath(import.meta.url)) {
```

## 3. 🟡 The signup form accepts usernames the relay rejects

- [x] Addressed
- [ ] Dismissed

`src/components/AuthView.vue:41` validates with `[A-Za-z0-9\-_]+`. chel
validates with `NAME_REGEX` (`src/serve/routes.ts:42` in okTurtles/chel):

```js
/^(?![_-])((?!([_-])\2)[a-z\d_-]){1,80}(?<![_-])$/
```

The server rule is stricter in three ways the form does not know about:

- lowercase only, so `Alice` passes the form and fails at the relay
- cannot start or end with `-` or `_`, so `_alice` and `alice-` fail
- no repeated separator, so `al__ice` and `al--ice` fail

`registerSalt` is the first call that hits the server, so the user gets
`POST /zkpp/register/Alice failed: 400` through the generic branch in
`request()` (`src/chelonia/auth.js:35`). For a signup form that is not a usable
message.

Mirror the server rule in the form so the mistake is caught before any request:

```diff
-        pattern="[A-Za-z0-9\-_]+"
-        title="Letters, numbers, hyphen and underscore"
+        pattern="(?![_-])((?!([_-])\2)[a-z\d_-]){1,80}(?&lt;![_-])"
+        title="Lowercase letters, numbers, hyphen and underscore. Cannot start or end with a hyphen or underscore."
```

Safari only shipped lookbehind in 16.4, so if that matters, drop the trailing
lookbehind from the HTML pattern and check the full rule in `submit()` instead.
Either way the comment in the code should say where the rule comes from, since
it has to stay in step with chel.

## 4. 🟡 "The username may already be taken" is attached to the wrong call

- [x] Addressed
- [ ] Dismissed

`src/chelonia/auth.js:189` wraps the failure of
`chelonia/out/registerContract`. But a taken username never reaches that call.
`POST /zkpp/register/:name` in chel checks the name first and returns 409:

```js
const lookupResult = await sbp('backend/db/lookupName', name)
if (lookupResult) {
  // If the username is already registered, abort
  throw new HTTPException(409)
}
```

So the actual "already taken" path fails inside `registerSalt` and surfaces as
`POST /zkpp/register/bob failed: 409`, while the friendly message is shown for
things that are usually something else entirely (relay down, rate limit, a bad
salt token).

Handle the 409 where it happens and let the `registerContract` failure say
something honest:

```diff
 async function registerSalt (username, password) {
   const keyPair = boxKeyPair()
   const r = bytesToB64(keyPair.publicKey).replace(/\//g, '_').replace(/\+/g, '-')
   const path = `/zkpp/register/${encodeURIComponent(username)}`
 
-  const { p, s, sig } = await request(path, form({ b: hash(r) })).then((r) => r.json())
+  const first = await fetch(`${API_URL}${path}`, form({ b: hash(r) }))
+  if (first.status === 409) throw new AuthError('That username is already taken.')
+  if (!first.ok) throw new AuthError(`Could not start signup: ${first.status}`)
+  const { p, s, sig } = await first.json()
```

and at line 189:

```diff
-    throw new AuthError('Could not create the account. The username may already be taken.', { cause: e })
+    throw new AuthError('Could not create the account.', { cause: e })
```

## 5. 🟡 A failed boot shows a logged-in session backed by nothing

- [x] Addressed
- [ ] Dismissed

`src/main.js:6-12` mounts the app in `.finally()`, so the UI comes up whether
or not `startChelonia()` succeeded. If `chelonia/configure` throws, or
`restoreSession()` cannot reach the relay, the saved state still has
`loggedIn`, and `state._kv` still has the last known todos. `App.vue` renders
`TodoApp`, `currentTodos()` reads the stale mirror, and the user sees their
list as though nothing is wrong. Every write then fails with "That change could
not be saved."

Showing stale data as live data is the wrong failure for an app whose whole
premise is that the server is authoritative. Track the failure and say so:

```diff
+let bootError = null
 startChelonia()
-  .catch((e) => {
-    console.error('[todomvc] could not start Chelonia', e)
-  })
+  .catch((e) => {
+    bootError = e
+    console.error('[todomvc] could not start Chelonia', e)
+  })
   .finally(() => {
-    createApp(App).mount('#app')
+    createApp(App, { bootError }).mount('#app')
   })
```

and have `App.vue` render a short "cannot reach the server" message instead of
`TodoApp` when `bootError` is set. A retry button is a bonus, not required.

## 6. ⚪️ `logout()` can write the state back after clearing it

- [x] Addressed
- [ ] Dismissed

`src/chelonia/auth.js:256-261`:

```js
export async function logout () {
  delete state.loggedIn
  await sbp('chelonia/reset', { contracts: {} })
  sbp('chelonia/kv/refreshFilters')
  clearSavedState()
}
```

The watcher in `state.js` uses `flush: 'post'`, so it runs after the current
render tick. `refreshFilters` on line 259 can touch `_kv`, which schedules the
watcher, and that scheduled run happens after `clearSavedState()` on line 260.
The entry then reappears holding an empty state.

Nothing secret survives, since `chelonia/reset` has already cleared
`secretKeys`, so this is cosmetic rather than a leak. But the README says
logging out clears the saved state, and it is easy to make that true. Either
stop the watcher for the duration, or clear on the next tick:

```diff
-  sbp('chelonia/kv/refreshFilters')
-  clearSavedState()
+  sbp('chelonia/kv/refreshFilters')
+  await nextTick()
+  clearSavedState()
```

Returning the `watch` handle from `persistState()` and calling it in `logout()`
is the tidier version, and it also stops the pointless full-state stringify
during logout.

## 7. ⚪️ Editing the contract without bumping `VERSION` orphans existing accounts

- [x] Addressed
- [ ] Dismissed

`scripts/build-contracts.mjs:18` pins `VERSION = '1.0.0'`, and line 60 passes
`--overwrite` to `chel pin`. Change one line in `src/contracts/identity.js` and
the next `npm run contracts` quietly produces a new manifest CID under the same
version. The app is rebuilt against the new CID, but every contract already on
the relay still references the old one, so existing accounts stop loading with
a manifest mismatch.

For a demo people will edit while reading, that is a confusing failure. Either
fail loudly when the source changed but the version did not, or say in the
README that changing the contract means bumping `VERSION` and starting from a
clean `data/`.

## 9. ⚪️ `crypto.randomUUID()` is unavailable outside a secure context

- [x] Addressed
- [ ] Dismissed

`src/chelonia/todos.js:63` uses `crypto.randomUUID()`. It only exists in a
secure context. `http://localhost:8000` qualifies, so the documented path is
fine, but the moment someone opens the demo from another machine on
`http://192.168.x.x:8000` to try the two-window sync, `crypto.randomUUID` is
`undefined` and adding a todo throws.

`crypto.getRandomValues` is available everywhere and is a two-line fallback, or
just note in the README that the demo has to be reached over localhost.
